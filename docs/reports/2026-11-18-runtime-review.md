## Architecture and the recent module changes

Chappe owns network I/O, Foy the Servlet lifecycle, Cassini REST dispatch, Champollion serialization and Vauban object construction and CDI lifetimes. The runtime's extensions choose the implementations and connect them. For example, mounting Cassini as a servlet under Foy lets REST endpoints participate in the servlet security pipeline. Kerckhoffs reports eight passing REST security cases for this arrangement. Its coverage page also names pending LDAP, OpenID Connect and expression-based login cases. The assembly a user deploys determines which security contract applies. [ExtensionLoader](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-core/src/main/java/io/vidocq/runtime/core/ExtensionLoader.java) · [tck.adoc](https://codefloe.com/Vidocq/kerckhoffs/src/commit/78404bdd68728663312793f92b8071f814066cf3/docs/en/modules/ROOT/pages/tck.adoc)

The important architectural boundary crosses repositories. The Maven plugin selects and sometimes rewrites dependencies, Vauban constructs a module graph or supplies generated components, and the runtime decides which loader extensions see. Each can be locally correct while the packaged application loses a provider, migration or interceptor. The integration fixture deliberately uses a library to locate an application resource, loads a service available only through a provider method, and exercises a transitive JDK module. Those are stronger observations than counting resolved modules. [VaubanLayerFactory](https://codefloe.com/Vidocq/vauban/src/commit/bd38e9526b82d126a6b528b7cb179a100753210c/vauban-classloader/src/main/java/io/vidocq/vauban/classloader/VaubanLayerFactory.java) · [AppLayerImageIT](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-integration-tests/vidocq-runtime-it-app-layer/src/test/java/io/vidocq/runtime/it/applayer/AppLayerImageIT.java) · [AppLayerPackageIT](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-integration-tests/vidocq-runtime-it-app-layer/src/test/java/io/vidocq/runtime/it/applayer/AppLayerPackageIT.java)

The placed proxy had the same binary name, module and delegated return values in both packaged forms. In the child layer Vauban can transform class definitions. In the image the staged subclass calls a library constructor with default arguments. A constructor that registers a listener, acquires a resource or rejects a default argument can therefore change observable behavior. These consequences are inferences from the measured extra call. For a producer returning such a class, an interface return type avoids this particular dependency on construction. [AppLayerRunIT](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-integration-tests/vidocq-runtime-it-app-layer/src/test/java/io/vidocq/runtime/it/applayer/AppLayerRunIT.java) · [AppLayerImageIT](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-integration-tests/vidocq-runtime-it-app-layer/src/test/java/io/vidocq/runtime/it/applayer/AppLayerImageIT.java) · [StagedProxies](https://codefloe.com/Vidocq/vidocq/src/commit/818a4003fb514c5c67e3c73393feedc9e042b7a4/vidocq-runtime-maven-plugin/src/main/java/io/vidocq/runtime/maven/StagedProxies.java)

## Release decision

**Prioritize one cross-format acceptance gate for the same built application.** Retain the existing focused tests. For a release candidate, exercise a protected endpoint through Foy/Cassini, a normal-scoped synthetic bean, a package-owned library proxy and a resource directory. Compare provider counts, authorization decisions, interceptor execution, constructor side effects and resource ownership across the production JAR and image. Require the expected frozen/start extension lists and check the reachable code-generation fallbacks. Run the same artifact once with invalid runtime security configuration. This would catch failures a green model TCK or a clean startup report alone cannot see.

**For the maintainer's decision today:** the evidence supports the change in image topology and the recent BCE corrections. The library-constructor difference is the clearest remaining compatibility issue. The build chain is the most important security scope to add to the existing threat model. I would make claims of cross-format equivalence only for the behaviors measured on the artifact being released.

### Repeating the focused checks

Use disposable checkouts at the revisions above. From the Vidocq and Vauban roots respectively, the focused reactor commands are:

./mvnw -ntp -pl vidocq-runtime-maven-plugin -am test \
  -Dtest=ApplicationLayerTest,RefusedRecordTest,StagedProvidesTest,StagedProxiesTest,ImageLaunchTest \

For the functional observations, I installed the audited Vauban and Vidocq plugin reactors in the temporary repository, used the runtime's filtered `it-app-layer` fixture, and ran Maven's `package` lifecycle phase **in the same invocation** as `vidocq:package` and `vidocq:jlink`.
